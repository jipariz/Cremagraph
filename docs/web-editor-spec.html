OnlyShots web editor

Superseded. This describes the DOM editor that the web ran until October 2026. The web now runs the same Compose editor as the phones and the desktop (EditorApp); see the README's “The web editor”. Kept for the record.

Specification of what the editor at onlyshots.vercel.app does today, written as the starting point for a redesign. Everything here is current behaviour read off the implementation, not intent: where something is awkward it is described as it is, and the rough edges are listed at the end rather than smoothed over.

1. What it is

A single-page editor that burns an espresso machine's shot graph into a video of that shot and exports an MP4. It is the editor half of the OnlyShots phone apps; filming and the shot library stay on the phones, because a browser has no equivalent of the camera's pre-roll trigger.

The whole job is four steps, in one screen, with no account and no server:

  1. Choose a video of a shot.
  2. Attach the shot data that goes with it.
  3. Line the two up, trim, and place and style the graph.
  4. Export a 1080 × 1920 MP4.

Nothing is uploaded and nothing is stored: the video is read, drawn and encoded inside the page, and a reload loses all of it.

2. Constraints the design has to live with

Constraint Consequence for the UI
Output is always 9:16, 1080 × 1920 The preview is a fixed 9:16 frame; wider source video is centre-cropped, exactly as the export crops it. There is no choice of aspect or resolution.
Export needs WebCodecs VideoEncoder Chrome, Edge and Safari 16.4+ can export; Firefox cannot and is told so when it presses the button, not before.
Export is silent There is no audio control anywhere; the source's sound is dropped.
Export runs frame by frame in the page It takes real time (roughly the clip's own length on a laptop), blocks nothing visually except the button, cannot be cancelled, and has a progress bar.
Shot-by-URL is a browser fetch It only works where the host sends CORS headers. SproFiler does not, so the file picker is the reliable path and the URL field needs its caveat in the copy.
No persistence of any kind No projects, no recent files, no undo, no autosave. Every reload starts empty.
The overlay is rendered from a shared scene builder Graph styles, layouts and the geometry of the card are fixed by the phone apps' engine. A redesign can change the page around the card, but changing the card itself changes all three platforms.

3. Anatomy

Two regions, which the breakpoint rearranges but never changes in content.

Stage

The 9:16 picture with the overlay drawn on it, the filmstrip under it, and a transport row: play/pause, 0:00.0 / 0:45.0, and a hint line.

Panel

Everything else in one column, in this order: banners, video, shot, style, data, layout, position, transparency, export.

Viewport Layout
> 900 px Two columns: stage on the left (picture capped so it fits the window height), a 380 px panel on the right. The page scrolls as one.
≤ 900 px One column. The stage sticks to the top of the viewport while the panel scrolls under it; the picture is capped at 42 vh and centred, the filmstrip spans the full width, the hint line is hidden, and the export button sticks to the bottom with safe-area padding.

4. Features

4.1 Load a video

  • Control: choose a video, a file input with accept="video/*". The chosen file's name is shown beside it.
  • The file is opened locally. The editor reads width, height, duration, average frame rate (fallback 30 fps) and whether the browser can decode it.
  • On success: the picture appears, trim resets to the whole clip, the playhead goes to 0, and the filmstrip is built.
  • Undecodable file → banner “this browser cannot decode that video”; unreadable file → “could not read that video: …”.
  • Replacing the video keeps the shot, the overlay settings and the shot-start flag, and resets the trim.

4.2 Attach a shot

Three ways in, one parser behind them:

  • from a file — file input, .shot, .json.
  • sample shot — loads a bundled 31 s shot, so the editor can be tried with no file at hand.
  • load url — a URL field plus a button; CORS applies.

The format is the Gaggiuino shot JSON that SproFiler, visualizer.coffee and the machine's own GET /api/shots/{id} all produce: parallel arrays under datapoints, time in deciseconds, every reading ten times its real value. Pressure, flow, weight, weight flow, temperature, their targets and phase transitions are read; a series the file does not carry is left out rather than guessed.

  • On success the panel shows profile · machine · length, e.g. Londinium declining · Gaggiuino · 0:31.0.
  • Parse failure → red banner “that file is not a Gaggiuino shot: …”; fetch failure → “could not fetch that URL: blocked, probably by CORS”.
  • Attaching a shot does not move anything: the flag, trim and overlay placement stay as they were.

4.3 Preview and playback

  • The picture is an HTML video element; the overlay is a canvas on top of it, drawn every animation frame at the video's current time.
  • Playback is clamped to the trim: reaching the out point pauses and rewinds to the in point. Pressing play outside the trim jumps to the in point first.
  • The time label reads playhead / clip length in m:ss.t.
  • With no shot attached the picture plays with no overlay.

4.4 Place the graph

  • Drag inside the graph card to move it; drag its bottom-right corner to resize. Both are direct manipulation on the picture.
  • A dashed outline and a corner grip mark it, and the cursor switches to move / nwse-resize. Neither is drawn into the export.
  • The card is clamped to the frame and to a minimum size (120 × 70 at the 390-wide reference frame). It cannot be rotated, and only the bottom-right corner resizes.
  • position — three buttons, top / middle / bottom, snap the card vertically without changing its size.

4.5 Trim, and line the shot up

One canvas filmstrip, 72 px tall, carrying twelve thumbnails sampled across the clip. Everything on it is dragged directly; the grab radius is 14 px and the nearest handle wins, with the shot flag winning ties.

Mark Looks like Behaviour
Trim in / out Two full-height white bars with a grip line; outside them the strip is dimmed Drag to set the exported range. Minimum span 0.1 s. Dragging the in handle seeks the picture to it.
Shot start flag Orange vertical line with a square at the top Where the shot's t=0 sits in the video. Drag anywhere in the clip. This is the only alignment control.
Shot band Orange bar along the bottom, flag to shot end, with a short end tick Shows the recording's own length, which cannot be edited — only moved, with the flag.
Overrun Hatched torn edge where the band leaves the strip, plus a line of text under it Appears when the shot runs past the end of the clip: “the shot runs 0:12.9 past the end of the clip”.
Playhead Thin white line Dragging anywhere that is not a handle scrubs, clamped to the trim.

The graph is drawn at video time minus flag, so moving the flag slides the whole graph along the clip; before the flag the overlay shows the shot's first moment, and after its end, the last.

4.6 Style the graph

Control Type Values
style Select match machine (picks by the shot's source) plus nine named styles: Tiles, Gaggiuino web, Gaggiuino screen, GaggiMate, Decent app, Decent Insight, Decent Insight dark, Wendougee, Minimal.
data Six toggle chips pressure, flow, weight, weight flow, temp, targets. Each carries a colour swatch from the current style. Default on: pressure, flow, weight, targets.
layout Select graph + readings (default), graph, readings
position Three buttons top, middle, bottom
transparency Range + live % label 20 % to 100 %, snapped to 5 % steps, default 100 %

4.7 Export

  • One button, export mp4, enabled as soon as a video is loaded — a shot is not required, and exporting without one just re-encodes the trimmed clip.
  • Decodes every frame inside the trim, crops it to 9:16, draws the overlay for that frame's own timestamp, and encodes H.264 at the source's frame rate into an MP4. Output 1080 × 1920, silent, timestamps rebased so the file starts at zero.
  • Progress is a bar under the button; the banner reads “rendering…” and then “saved to your downloads”. The file is named <video>-onlyshots.mp4 and goes through the browser's own download.
  • Failures are banners: “this browser has no VideoEncoder: Chrome, Edge or Safari 16.4 and up can export”, “nothing to export in that range”, “export failed: …”.

6. Current visual language

Flat Metro surfaces taken from the phone apps: no rounded corners, no gradients, no elevation, Open Sans at 300 / 400 / 600, 44 px minimum touch targets, labels in lowercase.

  • #120D0B page
  • #1C1412 panel
  • #2A1F1C raised
  • #F5EFEC text
  • #B9A9A2 secondary
  • #7D6C66 dim
  • #EF4E2B accent
  • #A8741A warning
  • #8A2B14 error

The orange is the shot: the flag, the band, the accent on the primary button. White is the trim and the playhead. Nothing else is coloured.

8. Rough edges a redesign should know about

ThingToday
bug Unavailable data chips A chip is meant to grey out when the shot carries no such series. The check is written so that an enabled chip never greys, so the state is only ever visible on chips that are already off.
bug Phase labels Two phase transitions close together print their labels on top of each other (“phase 2phase 3”). This is in the shared scene builder, so it shows on the phones too.
gap No undoNothing is reversible; the only way back is to redo the gesture.
gap No keyboard or screen-reader pathThe filmstrip and the overlay are canvases with pointer handlers only. Nothing is focusable, there are no ARIA roles, and the sliders and selects are the only keyboard-reachable controls.
gap Thumbnails appear lateBuilding the filmstrip takes a second or two on a long clip, with no placeholder or spinner: the strip is simply empty until it is not.
gap Export cannot be cancelledOnce started it runs to the end; the only escape is a reload, which loses the session.
gap No fine alignmentThe flag is dragged on a strip where one pixel is a large fraction of a second on a long clip. There is no nudge, no numeric entry, and no audio waveform to align against — the phones detect the pump sound, the web does not.
gap No zoom on the stripTrimming a 5-minute clip to a 30-second shot happens at full-clip scale.
rough Hint text carries the UIThree separate explanatory paragraphs do the work that affordances should.
rough Error reportingFailures are one amber or red bar at the top of the panel, with raw exception text appended.
rough Desktop wastes the widthOn a wide screen the picture is capped by height and the panel is a fixed 380 px, leaving a large empty gutter.

9. Out of scope

Deliberately absent, and not oversights: recording (the camera and its pre-roll trigger live on the phones), a library or any persistence, machine connection over Wi-Fi or Bluetooth, shot history, audio in the export, 4K, multiple shots in one video, sharing or hosting of the result, and accounts.
